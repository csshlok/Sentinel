<objective>
Replace the plain restricted-token launch in `spawn_restricted_supervised` with a genuine Windows
AppContainer boundary: a low-box token carrying a real package SID and at least one capability SID,
combined with the existing `DISABLE_MAX_PRIVILEGE` restricted token, plus an explicit, additive ACL
grant on the launched process's working directory (the selected repository) so ordinary reads/writes
still succeed. This closes SBOX-01 (genuine AppContainer boundary, not just a restricted token) and
SBOX-02 (repository read/write survives) at the lowest layer of the stack, and is the exact mechanism
`PROCESS_SUPERVISOR_AND_CONTAINER_SHARING_PLAN.md` section A.5 flags as the highest-risk piece still
undone: the earlier Low-integrity attempt was denied ordinary Medium-integrity repository writes
because it had neither a package SID nor an explicit per-resource ACL grant -- this plan adds both.

Purpose: prove, with a real Windows Job Object/AppContainer/ACL end-to-end path and a real automated
test on this actual Windows machine, that the mechanism works before Phase 2 narrows the capability
set and Phase 3 adversarially attacks it.
Output: `process_supervisor.py` can spawn a process whose live token independently verifies as a
genuine AppContainer, and that process can create/edit/delete files in the repository it was launched
against.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Launched agent process <-> host OS/filesystem | The agent process (potentially compromised or misbehaving) runs inside the new AppContainer boundary; everything outside the granted repository ACE and granted capability SIDs must remain unreachable. |
| Planner/implementer <-> real Windows security primitives | Getting a Windows security API subtly wrong (e.g. trusting a return code without independent verification) can look like a boundary while providing none -- the exact "safety theater" failure this project's own principle forbids. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|------------------|
| T-01-01 | Spoofing | `spawn_restricted_supervised` | high | mitigate | Independently re-query the live spawned process's own token via `OpenProcessToken`+`GetTokenInformation(TokenIsAppContainer)` before `ResumeThread`; terminate and raise rather than trust `CreateLowBoxToken`'s/`CreateProcessAsUserW`'s return codes alone (mirrors `signal_control.py`'s `_verify_actually_suspended`). |
| T-01-02 | Elevation of Privilege | `create_appcontainer_sid`/`create_appcontainer_token`/`grant_appcontainer_repository_access` | high | mitigate | Any failure in AppContainer profile/SID creation, capability resolution, low-box token creation, or the ACL grant raises `AppError` and aborts the launch; there is no code path that falls back to launching under the old restricted-token-only or unrestricted boundary while claiming AppContainer was applied (Task 2's `test_appcontainer_setup_never_falls_back_to_a_weaker_boundary_silently`). |
