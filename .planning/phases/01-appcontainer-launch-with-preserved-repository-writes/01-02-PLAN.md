<objective>
Wire Plan 01's AppContainer primitives through the full `AgentLauncher.launch()` path so the boundary
Plan 01 proved at the `process_supervisor.py` primitive level is also true at the outward-facing
surface every other caller (routes, CLI, TUI in later phases) actually uses, and prove the same two
facts (genuine AppContainer applied, repository writes still work) end to end through that full path.
Also correct the one now-stale claim ("the caller integrity level is retained") that Plan 01 makes
untrue by construction, in both the production disclosure string and the one existing test that
asserts it. Closes the same SBOX-01/SBOX-02 requirements as Plan 01, at the launcher layer instead of
the primitive layer.

Purpose: prove the mechanism survives the one layer of indirection (`launch()`'s `process_factory`
closure) between the low-level primitive Plan 01 tested and the actual public
`AgentLauncherPort.launch` surface, and that a setup failure fails loud at this layer too.
Output: `AgentRun.authority_reduction` truthfully names the applied AppContainer SID after a real
launch; a forced AppContainer failure produces an `ERROR` `AgentRun`, never a silently-weaker `PASSED`
one.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| `AgentLauncherPort.launch` caller <-> the actual spawned process | The public surface every future caller (routes, CLI, TUI) uses must report the boundary that was actually applied, not a stale or aspirational one. |
| Launcher-level error handling <-> a partially-constructed AppContainer boundary | A failure raised deep inside `process_supervisor.py` must surface as a refused launch at the `AgentLauncherPort` surface, not as a launch that quietly proceeded under less protection than claimed. |
